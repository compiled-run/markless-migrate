# Markless repros from the kitchen-sink port

Each page here is the smallest `.tsrx` that shows one defect the port hit, on the published Markless 0.9.0 packages. They
are pages of one small app, so a single build shows all of them:

```bash
npm install            # or link ../node_modules
npx vp build
PORT=4540 node .output/server/index.mjs
node verify.mjs http://127.0.0.1:4540
```

`verify.mjs` drives each page in Chromium and prints `REPRODUCED` or `not seen` with what it saw. Run it against a fresh
server: `loop-variable-shadows-async` runs last because, when it reproduces, the server stops answering.

`lib/slow.ts` stands in for a fetch: it answers after 500 ms (`quick`: 50 ms) and logs whether it ran on the server or
in the browser.

| Page                                                              | Expected                                                                                                                        | Actual on 0.9.0                                                                                                                                                                                                                                                                                                                           | What the port does instead                                                                                                                                          |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `child-async-not-streamed` (with `components/child-async.tsrx`)   | An `@try` in a component the page renders streams its answer, as the same `@try` in the page does                               | The server runs the recipe, the response ends on `@pending`, and the browser runs the recipe a second time                                                                                                                                                                                                                                | Every async read and its `@try` live in the page component itself                                                                                                   |
| `shared-in-async-recipe`                                          | A recipe that reads a page-scoped `shared()` field reruns when it changes                                                       | The recipe throws `undefined` on the server and in the browser: `@catch` shows "caught undefined", and the fetch never runs                                                                                                                                                                                                               | A page `state()` (`version`) is the invalidation signal; `shared()` only feeds synchronous reads (the Users tab's address)                                          |
| `state-from-prop-recipe`                                          | A recipe that reads a `state()` seeded from a page prop reruns in the browser after a click                                     | When the answer comes inside the 250 ms pending deadline and the `@try` has a `@catch`, the browser evaluates the seed again with no props: `Cannot read properties of undefined (reading 'pathname')`, and the new value never shows. The same happens with `state(http...)`, the copy `MARKLESS_SERVER_ONLY_PROP_BROWSER_READ` asks for | Recipes read props, or consts derived from them, directly; every `state()` seed that reads a prop is written `onServer ? <prop> : <browser value>` (`lib/where.ts`) |
| `async-row-reads-prop`                                            | An `@for` row inside `@try` that reads a page prop renders when the list changes in the browser                                 | The row is added, and the page throws `reading 'pathname'`: the browser evaluates the row's prop read with no props                                                                                                                                                                                                                       | Rows read only their own fields; the active row is marked in the recipe                                                                                             |
| `navigation-reruns-recipe` (from `navigation-start`)              | Arriving in place on a page whose data is still on its way, the server's streamed answer fills `@pending`                       | The browser runs the recipe again after the swap: two fetches (server and browser), and the answer shown is the browser's, about half a second after the server had it                                                                                                                                                                    | None: in the port each such navigation calls the mock API twice and the browser asks `/api/...` for what the server already rendered                                |
| `arm-link-handler` (from `navigation-start`)                      | An `<a onClick>` inside `@try` runs its handler after an in-place arrival, as on a fresh load                                   | The handler does not run; the router follows the link. A `<button>` beside it works                                                                                                                                                                                                                                                       | The invoice page's "Show Notes" link has the `href` its handler would push, so following it lands on the same result, one round trip later                          |
| `sync-from-pending-async` (from `navigation-start`)               | A synchronous `computed()` over an async one waits for it                                                                       | After an in-place arrival it runs while the async value is still pending and reads `undefined`: `... is not iterable`                                                                                                                                                                                                                     | `Array.isArray(users) ? users : []` in the users list                                                                                                               |
| `empty-derived-list-pending`, `empty-derived-list-attribute-rows` | A synchronous list filtered from an async one shows no rows when nothing matches, and the matches when the filter changes again | When the `@try` has a `@catch`, or the rows carry an attribute, an empty list switches the `@try` to `@pending` though nothing is loading, and it stays there                                                                                                                                                                             | The users list keeps one hidden row when nothing matches                                                                                                            |
| `empty-derived-list-with-empty`                                   | An `@empty` arm shows while the filtered list is empty                                                                          | `Failed to execute 'removeChild' on 'Node'`, and the rows never come back                                                                                                                                                                                                                                                                 | No `@empty` arm; the hidden row above                                                                                                                               |
| `loop-variable-shadows-async`                                     | `@for (const item of rows)` beside an async `computed()` also named `item` renders both                                         | The response never ends; the server process spins at full CPU and its memory grows until it is killed. Looping over the async list directly, the build refuses it with a misleading `MARKLESS_PUBLIC_RENDER_GATE_PLAN_DISAGREEMENT`                                                                                                       | The users list loops over `row`                                                                                                                                     |
| `async-optional-and-whole`                                        | `{data?.text}` beside `{JSON.stringify(data)}` in one `@try` streams in                                                         | The stream ends after `@pending` (`net::ERR_INCOMPLETE_CHUNKED_ENCODING`) and the page never finishes loading. `{data?.text}` alone is refused at build time                                                                                                                                                                              | The user recipe returns `{ name, json }` and the `@try` reads those two fields                                                                                      |
| `textarea-value`                                                  | `<textarea value={text}>` shows the text, as `<input value>` does                                                               | The server writes a `value` attribute, which a textarea ignores: the field is empty                                                                                                                                                                                                                                                       | The text is the textarea's child                                                                                                                                    |
| `assignment-value`                                                | `f((count = 5))` passes 5                                                                                                       | It passes `undefined`; the port's sandbox panel stored the string "undefined" in sessionStorage this way                                                                                                                                                                                                                                  | The state is assigned on its own line                                                                                                                               |

Not reproduced here because it is fixed on Markless main (#205) after 0.9.0: a form whose `onSubmit` calls
`preventDefault()` is still submitted by the browser when its handler loads on first use. The port's forms carry
`method="dialog"`, which submits nowhere.
